# Omakron

A native Omarchy bar plugin for scheduled Claude Code routines. Choose a prompt,
model, working folder and schedule; see upcoming routines, change them, and
inspect saved results. Routines run with Claude Code's usual tools and no
permission prompts, and the model's own result is what a run shows. Read
[docs/PHILOSOPHY.md](docs/PHILOSOPHY.md) for the direction.

The native popup connects to a local service for routine editing and execution.
Cron schedules include timezone validation and five-occurrence previews.
Upcoming shows future occurrences grouped by day. All includes paused routines.
Recent lists runs by creation order, and an older completion cannot replace a
selected run. Run details show the saved prompt, requested and resolved models,
the model's result, and bounded diagnostic tails. Disconnected details remain marked stale.

Retry is explicit, links to the original run, and uses the current saved
revision. Refresh never retries. Soft delete
hides the routine and cancels waiting runs while preserving active work and history.

Output settings accept 1 to 8192 KiB per stream and 1 to 3650 retention days.
The supervisor checks output growth every 100 ms, stops oversized runs, and
bounds the retained prefix even if the child exits between checks. Temporary
captures can exceed that threshold between checks. Diagnostic previews show the
last 16 KiB. Cleanup requires preview and confirmation, removes only expired
successful diagnostics, and keeps results and all failed output.
The socket refuses responses above 1 MiB with an explicit error; full output
remains in the run folder.

To verify the popup in a disposable nested Omarchy session:

```
python scripts/verify_popup.py --live-editor --out /path/to/new/evidence-folder
```

The test copies native components into a temporary directory and uses synthetic
Agents data. It preserves the daily shell configuration and stops its processes.

## Layout

- `manifest.json`, `ui/` — the Omarchy plugin (`omakron.routines`); the
  repository root is the folder the shell installs
- `src/omakron/` — service, worker, client, store, runner, the seeded
  routine, schedule evaluator, installer, checks
- `tests/` — product tests with a fake `claude` executable, a fake clock, and
  the real service run as a subprocess
- `packaging/` — reference systemd user unit generated by service setup

## Running the service by hand

The service can run in the foreground or through the packaged user unit.
It keeps its database and run output under `$XDG_STATE_HOME/omakron`
(default `~/.local/state/omakron`), reads `$XDG_CONFIG_HOME/omakron/settings.json`
if present, and listens on `$XDG_RUNTIME_DIR/omakron/service.sock`.

```
PYTHONPATH=src python -m omakron.service
PYTHONPATH=src python -m omakron.client status
PYTHONPATH=src python -m omakron.client routines
PYTHONPATH=src python -m omakron.client run-now <routine-id> --wait 660
PYTHONPATH=src python -m omakron.client run <run-id>
PYTHONPATH=src python -m omakron.client cancel <run-id>
```

On first start the service seeds one routine, "Folder summary", manual only
and paused. It asks the model to describe its working folder and write
`SUMMARY.md` there. Runs belong to the service: the client may exit at once,
and the result is read back later with `run` or `runs`.

Each routine chooses how Claude Code runs. `tools` is the CLI's `--tools`
value (`default`, `""`, or a comma-separated list), `permission_mode` is one
of the CLI's modes (`bypassPermissions` by default, since nobody answers
prompts during a scheduled run), `mcp_config` is an optional path to an MCP
config file, and `env_passthrough` lists extra environment variables the run
inherits beyond the session basics. `create-routine` takes the same choices as
flags:

```
PYTHONPATH=src python -m omakron.client create-routine --name "Nightly tidy" \
  --prompt-file prompt.txt --cwd /path/to/project --tools default \
  --permission-mode bypassPermissions --env GH_TOKEN
```


To repeat the real-CLI smoke test (one bounded model call under the existing
login, evidence written beneath the supplied scratch folder):

```
PYTHONPATH=src python scripts/smoke_vertical_slice.py --out /path/to/scratch
```

## Scheduling controls

Saved cron routines start paused. Enable the saved policy from the details
view to authorize recurring runs. Saving an edit pauses future
runs. Pause leaves active work alone and removes queued scheduled work.
Resume schedules the next future occurrence without catch-up.

The service skips missed occurrences beyond 60 seconds, prevents same-routine
overlap, and expires queued work after five minutes. Checkpoints and local-slot
guards survive restarts. Interrupted work is never replayed automatically.
The service does not enable lingering, wake timers, or execution while asleep.

The raw JSON client also exposes `set_enabled`, `set_dispatch`, and
`schedule_gaps`. For example, stop scheduled dispatch while keeping history:

```
printf '%s' '{"op":"set_dispatch","params":{"enabled":false}}' | python scripts/client.py request
```


## Installation and recovery

Omakron 0.1.0 has a preview-first installer and a separate service setup step.
Read [the installation guide](docs/INSTALL.md) for exact revision installation,
compatibility checks, private backups, upgrade, rollback, and retained-data uninstall.
Run `python scripts/manage.py <action>` to preview an action before applying it.
Cloning the plugin does not enable its widget or install its user service.
